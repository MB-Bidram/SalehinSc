SalehinSc — deployment and first use
====================================

The public GitHub Pages site contains the student interface only. The primary
teacher keeps a private local file named teacher.html. That file redirects to
the public app with a short-lived-in-practice, revocable bearer credential in a
URL fragment. The app validates the account with the Cloudflare Worker. The
GitHub Personal Access Token remains in Cloudflare and never enters the browser.

A. Preserve the school's data
-----------------------------
1. Back up the repository and its entire data/ directory.
2. Copy the updated application, worker/, wrangler.toml, scripts and workflow
   files into the existing repository.
3. Do not replace data/portal.json or data/ with sample files from an archive.
4. Keep repository owner, repository name, default branch and data scope aligned.

B. Configure the server-side GitHub credential
-----------------------------------------------
1. Create a GitHub fine-grained Personal Access Token scoped only to this
   repository. Grant Contents read/write, Issues read/write and Actions
   read/write. Metadata read is normally granted by default.
2. Run from the project root:

     npm ci
     npx wrangler login
     npx wrangler secret put GITHUB_TOKEN
     npx wrangler deploy

3. Paste the token only into Wrangler's secure prompt. It is stored as a
   Cloudflare Worker Secret; never place it in index.html, teacher.html,
   config.js, wrangler.toml, a URL, Git history or browser storage.
4. Put the deployed Worker URL in index.html's salehin-api meta tag and commit
   that public URL. It is not a secret.
5. Check https://YOUR-WORKER.workers.dev/v1/health for {"ok":true}.

The Worker is a fixed-repository publisher, not a general GitHub proxy. For a
new Pages origin, update ALLOWED_ORIGIN in wrangler.toml and redeploy.

C. Configure GitHub Pages and Actions
-------------------------------------
1. In repository Settings > Pages select GitHub Actions as the source.
2. Keep portal-publish.yml enabled with its existing minimum workflow permissions.
3. Commit the site and Worker changes to the default branch. Commits limited to
   data/** intentionally skip rebuilding the static site shell.
4. The Pages workflow explicitly excludes teacher.html even if someone
   accidentally force-adds it. Keep it ignored locally as well.

D. Existing v4 school: transition to the private local teacher file
--------------------------------------------------------------------
1. Back up the live repository and data/ directory.
2. Before the first deploy, remove the retired tracked teacher QR routes (run
   `git rm -f --ignore-unmatch teacher.html`, `git rm -r -f --ignore-unmatch teacher`,
   and `git rm -f --ignore-unmatch tools/staff-qr-maker.html`). Do this only for
   the old public entry files; keep any newly generated private teacher.html
   outside the repository.
3. Run npm ci and npm run migrate:primary-teacher. This creates
   data/teachers/teacher.json with the primary account ID only; it does not
   modify students, scores, messages or attachments.
4. Commit the new teacher directory and deploy the updated Worker/site.
5. The primary teacher enters once using the existing authorized access method
   on the updated site. In the roster, choose “ساخت / تعویض فایل خصوصی دبیر”.
6. Confirm the rotation. The app re-keys the primary account and downloads a
   new local teacher.html. The previous credential is revoked immediately.
7. Store the downloaded file in a private folder on the teacher's trusted
   computer. Do not commit it, upload it, email it or put it in a shared drive.
8. From then on, open the local teacher.html file for every teacher session.
   It redirects to the project Pages app; the hash is removed after validation.

This one-time use of the old access method is a migration bridge. After the new
file is issued, no teacher QR or public /teacher/ entry route is used.

E. Fresh installation (empty repository only)
----------------------------------------------
1. Create an empty public GitHub repository. Confirm that it has no live school
   data before initializing it.
2. Remove sample data only in this fresh working copy, then run:

     npm ci
     npm run bootstrap -- --owner OWNER --repo REPOSITORY --branch DEFAULT_BRANCH --name "مدیر مدرسه"

3. Bootstrap creates data/teachers/teacher.json and a private local teacher.html
   in the project root. It never prints the access key to the terminal. The
   generated file is ignored by Git and excluded from Pages deployment.
4. Keep teacher.html on the primary teacher's trusted device. Commit the
   application and encrypted data files, but never teacher.html.
5. Deploy Pages and the Worker as described above, then open teacher.html.

Never run bootstrap with --replace-seed on a populated live school. The script
refuses to replace a matching live catalogue, but backups and human review are
still required before changing production data.

F. Local teacher file lifecycle
-------------------------------
- Open the local teacher.html file to enter. The file redirects to the current
  project-relative GitHub Pages URL.
- To replace it, enter through the current file and choose “ساخت / تعویض فایل
  خصوصی دبیر”. The previous file becomes invalid when the account is re-keyed.
- Keep a secure backup of the file. A copy of the old file cannot be made valid
  again after rotation.
- The file contains an access key, not a GitHub PAT. Protect it as carefully as
  a school master key.

G. Windows setup wizard and connection settings
-----------------------------------------------
1. Run setup-salehinsc.bat from the project root. It checks Git/Node/npm, asks
   for owner, repository, branch and school name, previews changes, and
   preserves .git and data/.
2. It never commits, pushes, force-pushes, or stores a GitHub token.
3. In the signed teacher session, open the gear icon > GitHub Connection >
   Test Connection. The Worker checks its server-side credential, repository,
   branch, catalogue, Issues API and publishing workflow.
4. Replace/remove the PAT using Wrangler:

     npx wrangler secret put GITHUB_TOKEN
     npx wrangler secret delete GITHUB_TOKEN

Security note: a static site cannot protect a token typed into browser
JavaScript. The PAT stays server-side. The local teacher file contains only the
teacher access credential and must remain private.

H. Student QR papers
--------------------
- All students: roster > “چاپ برگه‌های QR”. Only active students receive cards.
- One student: choose the student's QR action, then print the paper.
- Replacement: from that student's QR dialog choose “تعویض و ابطال QR قبلی”.

There is no teacher QR generation, QR printing or teacher QR paper. Students
continue to use their personal QR codes.

I. Local checks
---------------

     npm ci
     npm run check
     npm test
     npm run serve

Open http://127.0.0.1:8080/ for the local site. Without a deployed Worker,
write operations remain unavailable. The private teacher file points to the
configured project URL and requires the deployed site and Worker to be online.

One-time cleanup of retired teacher QR files:
  npm run cleanup:retired-teacher-qr
