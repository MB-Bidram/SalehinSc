SalehinSc — deployment and first use
====================================

IMPORTANT: This project is a static GitHub Pages front end plus a small
Cloudflare Worker. GitHub Pages alone cannot securely authorize writes.
Do not paste a GitHub token into the website or into a public file.

A. Preserve the live school's data
----------------------------------
1. Make a private backup of the current repository and its data/ directory.
2. Copy the updated application, worker/, wrangler.toml, and workflow files
   into the existing repository.
3. Do NOT replace data/portal.json or data/ with the source ZIP's copy when
   updating a live school. The ZIP contains only a sample/legacy administrator
   seed and does not contain the school's actual student records or QR secrets.
4. Keep the repository name, default branch and data scope aligned. This ZIP's
   wrangler.toml targets MB-Bidram/SalehinSc, branch main, data/portal.json.
   Change those values only when deploying to a different repository/branch.

B. Configure the server-side GitHub credential
-----------------------------------------------
1. Create a GitHub fine-grained Personal Access Token for ONLY the SalehinSc
   repository. Grant:
     - Contents: Read and write
     - Issues: Read and write
     - Actions: Read and write
   Metadata read access is required by GitHub and is normally granted by default.
2. Install Node.js (current LTS) and run from this project directory:

     npm ci
     npx wrangler login
     npx wrangler secret put GITHUB_TOKEN
     npx wrangler deploy

3. Paste the token only into the Wrangler secret prompt. It is stored as a
   Cloudflare Worker secret. It must never be put in config.js, index.html,
   wrangler.toml, a GitHub commit, a QR code, or browser storage.
4. Wrangler prints a Worker URL similar to:
     https://salehinsc-api.<your-account>.workers.dev
5. Put that exact URL in index.html's existing meta tag:
     <meta name="salehin-api" content="https://salehinsc-api.<your-account>.workers.dev">
   Commit the HTML change. No token goes in this meta tag.
6. Check the health endpoint in a browser:
     https://salehinsc-api.<your-account>.workers.dev/v1/health
   It should return a small JSON response with ok: true.

The Worker configuration in wrangler.toml already restricts browser requests
 to https://mb-bidram.github.io. For a different Pages origin, change
ALLOWED_ORIGIN to that exact origin and redeploy. The Worker talks to the one
repository named by GITHUB_REPOSITORY; it is not a general GitHub proxy.

C. Configure GitHub Actions and Pages
-------------------------------------
1. In the repository, open Settings > Pages and select GitHub Actions as the
   publishing source.
2. Ensure the repository default branch is main (or update wrangler.toml and
   the data catalogue scope to match the actual default branch).
3. Keep .github/workflows/portal-publish.yml enabled. It needs the workflow's
   declared permissions: Contents: write and Issues: read. GitHub supplies its
   short-lived GITHUB_TOKEN to the workflow; no additional browser token is used.
4. Commit the application and workflow changes to the default branch. The Pages
   workflow deploys the site shell. Later commits that only change data/** are
   intentionally skipped by pages.yml, so score/message updates do not rebuild
   the website. This relies on Pages using GitHub Actions, not branch publishing.

D. First staff QR / migration of an existing school
---------------------------------------------------
1. Open the deployed Pages URL and scan the school's CURRENT administrator QR.
   Existing QR links without a separate QR grant still work as a migration path.
2. In the staff roster, choose "چاپ QR دبیران". If the current account uses the
   old root-key QR format, the first print automatically re-keys the encrypted
   admin dossier and signing identity, creates a new independent QR grant, and
   prints the new staff QR. The previous QR stops opening the current account.
3. Collect and destroy the old staff paper after checking the new QR on a second
   trusted device.
4. Choose "چاپ برگه‌های QR" to export active student papers. Legacy student QR
   grants are upgraded individually during this export. This needs their keys
   in the administrator vault; do not clear or overwrite the live data first.

The source ZIP's catalogue contains one encrypted administrator seed, no
student accounts, no messages/scores, and no recoverable QR secret. The old QR
secret is intentionally not stored in the public catalogue. If the school's
current staff QR has been lost, this archive cannot reconstruct it. Do not
replace a populated live catalogue with the archive seed as a workaround.

E. Fresh installation (new, empty repository only)
---------------------------------------------------
1. Create an empty public GitHub repository (or use a repository whose data/
   directory is confirmed empty and backed up).
2. Clear the sample data/portal.json and sample data/students/* from this
   working copy only after verifying that it is not the live school's data.
3. Run:

     npm run bootstrap -- --owner OWNER --repo REPOSITORY --branch DEFAULT_BRANCH --name "مدیر مدرسه"

4. The command prints one private QR fragment. Store it securely and generate
   its QR only locally. Never commit the fragment, its QR image, or a CSV of
   credentials. The bootstrap output is the only copy of that initial secret.
5. Commit the generated data/portal.json and data/students/ file, plus the
   application and workflow files. Deploy Pages and configure the Worker as
   described above.

Never run bootstrap with --replace-seed on a populated school. The script
refuses to replace a matching live catalogue, but backups and human review are
still required before changing production data.

F. Local checks
---------------

     npm ci
     npm run check
     npm test
     npm run serve

Open http://127.0.0.1:8080/ for the site. Without a deployed Worker the roster
is read-only and the page explains that setup is missing. Local preview URLs
use synthetic data only.

QR paper printing
-----------------
- Staff: staff roster > "چاپ QR دبیران". The QR itself is the secret; no secret
  is printed as readable text.
- Replace a leaked/lost staff paper: "تعویض QR دبیران". This invalidates the old
  grant immediately, re-keys the admin identity, and opens a new print sheet.
- All students: staff roster > "چاپ برگه‌های QR". It prints active student cards.
- One student: choose the student's "QR" action, then "چاپ برگه".
- Student replacement: from that student's QR dialog choose "تعویض و ابطال QR قبلی".

Use a private school printer. Deliver each student QR only to that student or
family. Do not keep unnecessary printed or digital copies.
